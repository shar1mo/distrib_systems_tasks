# Вопросы для самопроверки

1. Зачем нужны `variables` в GraphQL запросе? Почему нельзя просто склеивать строки?

- Variables нужны, чтобы безопасно подставлять данные в запрос без риска инъекций и чтобы сервер мог кэшировать и переиспользовать запрос. Склеивать строки небезопасно и неэффективно.

2. Из каких полей состоит стандартный JSON-запрос к GraphQL серверу?

- Стандартный JSON-запрос состоит из полей: "query" (текст запроса) и "variables" (словарь переменных).

3. Почему у GraphQL обычно только один URL endpoint?

- GraphQL обычно имеет один URL endpoint, потому что все операции (query, mutation, subscription) проходят через один точку, отличие только в теле запроса.

4. Что означает наличие поля `errors` в ответе сервера? Может ли оно прийти вместе с `data`?

- Поле errors означает, что произошла ошибка при обработке запроса. Оно может идти вместе с data при частичном успехе.

5. Как клиент должен обрабатывать ошибки, если HTTP статус ответа 200?

- Клиент должен проверять поле errors в JSON и корректно обрабатывать их, даже если HTTP статус 200.

6. В чем плюсы использования типизированных клиентов (например, Apollo Client или Relay) перед простыми HTTP-запросами?

- Типизированные клиенты дают автокомплит, проверку типов, удобную работу с кэшированием и оптимизацию запросов, что снижает ошибки и ускоряет разработку.
