# Вопросы для самопроверки

1. В чем разница между Forward Proxy (обычный прокси) и Reverse Proxy (обратный прокси)?

- Forward Proxy — это прокси для клиента. Клиент отправляет запрос прокси, а тот пересылает его в интернет. Клиент скрывает свой настоящий IP.

- Reverse Proxy — это прокси для сервера. Клиент обращается к прокси, а прокси решает, какой внутренний сервис обслужит запрос. Серверы за обратным прокси скрыты, клиент не знает их адресов.

2. Что такое Upstream в терминологии Nginx?

- Upstream — это группа серверов или конкретный сервис, к которому Nginx пересылает запросы. Например, можно определить upstream items_service { server 127.0.0.1:8101; }, а потом маршрутизировать к нему все /api/items запросы.

3. Зачем скрывать реальные IP-адреса сервисов от клиента?

- Чтобы защитить внутреннюю инфраструктуру от атак и не давать клиенту прямой доступ к сервисам.
Также это упрощает изменение внутренней структуры: можно перемещать сервисы на другие адреса без влияния на клиентов.

4. Какие еще задачи, кроме маршрутизации, может выполнять API Gateway (назовите хотя бы 2)?

- Аутентификация и авторизация — проверка токенов и прав доступа.

- Балансировка нагрузки — распределение запросов между несколькими экземплярами одного сервиса.

- Кеширование — уменьшает нагрузку на бэкенд, отдавая часто запрашиваемые данные из памяти.

- Лимитирование и защита от DDoS — контроль числа запросов от одного клиента.

5. Что произойдет, если Gateway упадет? Как можно от этого защититься?

Если Gateway перестанет работать, все клиенты потеряют доступ ко всем микросервисам, потому что они не видят их напрямую.
Защититься можно:

- Развернуть несколько экземпляров Gateway с балансировкой между ними (High Availability).

- Использовать автоматический перезапуск контейнера или системы (например, Docker restart policy или Kubernetes).
