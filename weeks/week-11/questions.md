# Вопросы для самопроверки

1. Зачем создавать пользовательскую сеть (bridge network) в Docker Compose, если есть дефолтная?

- Чтобы явно управлять сетью, изолировать сервисы и иметь стабильные имена (DNS) внутри проекта. Дефолтная сеть создаётся автоматически, но кастомная — более гибкая.

2. В чем разница между `build` и `image` в описании сервиса?

- build — Docker сам собирает образ из Dockerfile.
- image — используется уже готовый образ.

3. Что делает `depends_on`? Гарантирует ли он, что приложение в зависимом контейнере полностью инициализировалось?

- Определяет порядок запуска контейнеров. Не гарантирует, что сервис внутри контейнера полностью готов.

4. Как работают healthcheck-и и как использовать их в `depends_on`?

- Healthcheck проверяет состояние контейнера (например, через curl). С condition: service_healthy можно дождаться, пока сервис реально станет готов.

5. Как передать переменные окружения в контейнер через Compose (минимум 2 способа)?

- Через environment: в docker-compose.yml
- Через .env файл
- (ещё вариант — env_file:)

6. Почему Docker Compose редко используют в продакшене (хотя это возможно)?

- Потому что Compose не масштабируется и не управляет кластером. В продакшене используют Kubernetes или другие оркестраторы.
