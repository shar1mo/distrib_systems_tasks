# Вопросы для самопроверки

1. Почему мы создаем Deployment, а не сразу Pod?

- Deployment управляет подами: следит за количеством, перезапускает при падении, делает обновления. Pod сам по себе не восстанавливается.

2. В чем разница между Liveness и Readiness пробами? Что произойдет, если провалится каждая из них?

- Liveness — жив ли контейнер. Если провалится → контейнер перезапустится.
- Readiness — готов ли принимать трафик. Если провалится → под исключается из Service (но не перезапускается).

3. Что такое "requests" и "limits" для CPU и памяти? Почему важно их указывать?

- requests — минимальные ресурсы для запуска
- limits — максимальные ресурсы
- Важно, чтобы избежать перегрузки и корректно распределять ресурсы в кластере.

4. Как Service находит свои Pod-ы? (Подсказка: Labels & Selectors).

- Через labels и selectors: Service выбирает поды с совпадающими метками.

5. Какой тип сервиса (ClusterIP, NodePort, LoadBalancer) используется для внутреннего общения, а какой — для внешнего доступа?

- ClusterIP — внутреннее общение
- NodePort / LoadBalancer — внешний доступ

6. Что такое "Rolling Update" в контексте Деплоймента?

- Это постепенное обновление подов без остановки сервиса — старые поды заменяются новыми по очереди.
